# TypeStory — Product Requirements Document

**Version:** 1.0
**Date:** March 30, 2026
**Author:** Edward Greenblatt + Claude

---

## 1. Vision

TypeStory is a neon-drenched, Instagram-Stories-style typing game where your keystrokes write a unique AI-generated adventure. Pick your genre, pick your visual style, type your way through chapters while a live performance meter swings between awesome and terrible — then watch your story rendered as a comic book, anime sequence, or illustrated storyboard that's yours alone.

Play solo or with friends. Compare your branching stories at the end. Come back anytime — your stories are saved.

---

## 2. What TypeStory IS

- A typing game disguised as a story engine
- Visually loud — neon colors, dark backgrounds, glowing UI, arcade energy
- Addictive in the "one more chapter" way — the story pulls you forward
- Powered by generative AI — every playthrough is unique
- A social experience — multiplayer, shareable comic book output
- Accessible to anyone who can type — no skill floor, performance just shapes the story

## 3. What TypeStory is NOT

- Not a typing tutor (no lessons, finger placement drills, or curriculum)
- Not a long-form RPG (sessions are short — 5 to 15 minutes)
- Not text-heavy — visuals and pacing matter more than paragraphs
- Not a competitive esport — multiplayer is about story comparison, not leaderboards
- Not minimalist — this thing should feel alive and electric

---

## 4. Target Audience

**Primary:** Teens and young adults (13–25) who grew up on Instagram Stories, TikTok, and mobile games. They want something quick, visual, and shareable.

**Secondary:** Casual gamers of any age who like narrative games (Bandersnatch, AI Dungeon, Episode) and want a fresh twist. Also typing enthusiasts who find Monkeytype too sterile.

## 6. Key Features

### 6.1 Live Performance Meter

A circular gauge displayed during every typing challenge.

- **Shape:** Circle with a sweeping arc/needle
- **Left side:** Terrible (red/dark)
- **Right side:** Awesome (gold/neon glow)
- **Behavior:** Updates in real time as the player types. Each correct character nudges it right; each mistake nudges it left. The player can see their story fate shifting with every keystroke.
- **Visual polish:** The meter should glow, pulse, or change color intensity as it moves — it's not a quiet UI element, it's part of the spectacle.
- **Tiers displayed on the meter:**
  - Super Bad
  - Bad
  - Fine
  - Better
  - Good
  - Awesome

### 6.2 AI-Generated Stories

Every story beat is generated by an LLM (Claude API) based on:

- **Player profile:** Name, personality answers, chosen genre
- **Story context:** Running summary of what's happened so far
- **Performance:** How well they typed the last challenge (tier)
- **Chapter position:** Early = setup, middle = rising tension, late = climax/resolution

**Architecture:**
- Next.js API route or server action calls Claude API
- Prompt includes player state, story summary, and narrative instructions
- Response is a short story beat (2–4 sentences) + the next typing sentence
- Story text streams to the client for a word-by-word reveal effect
- A running story summary is maintained server-side so the AI has context without sending the entire history each time

**Guardrails:**
- System prompt enforces tone, length, and age-appropriateness
- Genre stays consistent within a session
- Story must resolve by the final chapter (AI is told how many chapters remain)

### 6.3 Genre & Visual Style Selection

**Genre options** (determines narrative tone and content):
- Fantasy
- Sci-Fi
- Horror / Suspense
- Mystery
- Romance
- Slice of Life / Coming of Age

**Visual style options** (determines how the final story is rendered):
- Comic Book (panels, speech bubbles, bold lines)
- Anime / Manga
- Fantasy Illustration (painterly, detailed)
- Pixel Art / Retro
- Watercolor Storybook
- Graphic Novel (dark, moody, cinematic)

At the end of the game, the story is re-rendered in the chosen style using AI image generation. Each chapter becomes a visual panel or page.

### 6.4 Neon Visual Identity

The entire UI should feel like it's glowing.

- **Background:** Dark (near-black or deep navy)
- **Primary palette:** Electric blue, neon pink, hot green, glowing purple, blazing orange
- **Accent / reward color:** Gold — used for "Awesome" tier, highlights, and celebratory moments
- **Typography:** Bold, large, high-contrast. Think arcade cabinet meets Instagram Stories.
- **Effects:** Glow, pulse, subtle animation. Correct keystrokes could spark. The meter should radiate. Transitions between screens should feel energetic, not sterile.
- **Inspiration:** Cyberpunk UI, arcade games, neon signage, festival visuals

### 6.5 Multiplayer — Story Comparison Mode

**Async multiplayer (v1):**
- A player generates a **share code** after completing a game
- Friends use the same code to play the identical seed (same genre, same chapter structure, same personality profile — or their own profile against the same prompts)
- After both finish, they can view stories side by side
- Highlights where the stories diverged based on different typing performance
- "Your story went dark in chapter 4 while your friend sailed through"

**Live multiplayer (v2 / future):**
- Two players type simultaneously through the same chapters
- Split-screen view of both performance meters
- Real-time "your friend just nailed chapter 3" notifications
- Side-by-side story reveal at the end

### 6.6 Persistence & Story Memory

**Local storage (v1):**
- Player profile, completed stories, ratings, and comic output are saved in the browser
- "Your Stories" library on the home screen shows past playthroughs
- Each saved story includes: date, genre, style, chapter ratings, final tier, and the generated story text
- Reopening the app shows your history — nothing is lost

**Accounts (v2 / future):**
- Optional sign-in (Google, email, or guest upgrade)
- Stories sync across devices
- Required for multiplayer features
- Enables a public profile / shareable story gallery

### 6.7 Personality Questions

Expanded from current 5 to be more meaningful. All answers feed into the AI story generation prompt.

**Current questions (keep):**
- Character name
- Gender (for pronouns)
- Companion choice (Cat, Dog, Dragon, Wolf)
- Place that feels like home (Forest, City, Ocean, Mountains)
- Session length

**Enhanced / new questions:**
- Comfort food → woven into story scenes (campfire moments, celebrations)
- Color identity → influences the visual tone of their story panels
- Preferred ending type (Triumph, Mystery, Peace, Surprise) → AI steers toward this
- What scares you? → AI uses this for tension/conflict beats
- What makes you laugh? → AI uses this for lighter moments

All answers are passed to the AI in the system prompt so the story genuinely reflects the player.

## 8. Technical Architecture

### 8.1 Stack
- **Frontend:** Next.js (App Router), React, TypeScript, Tailwind CSS
- **AI — Text:** Claude API (story generation, streaming responses)
- **AI — Images:** Image generation API (comic panels, style rendering)
- **State:** React state + localStorage (v1), database (v2)
- **Multiplayer:** Share codes stored server-side (simple key-value), WebSockets for live mode (v2)
- **Hosting:** Vercel
- **Repo:** github.com/fredhead88/typestory

### 8.2 AI Integration

**Story generation endpoint:** `POST /api/story`

```
Request:
{
  playerProfile: { name, gender, genre, style, answers },
  storySoFar: "compressed summary of chapters so far",
  lastPerformance: "awesome" | "good" | "fine" | "bad" | "super_bad",
  chapterNumber: 4,
  totalChapters: 7
}

Response (streamed):
{
  storyBeat: "The cavern opened into a vast underground lake...",
  nextSentence: "crystal light reflected off the still dark water below",
  storySummary: "updated running summary for next call"
}
```

**Image generation endpoint:** `POST /api/illustrations`
- Called once at game end with the full story + chosen visual style
- Returns one image per chapter
- Can be processed in background while player reads ending screen

### 8.3 Data Model

```
PlayerProfile {
  name: string
  gender: "male" | "female" | "neutral"
  genre: Genre
  visualStyle: VisualStyle
  sessionLength: 3 | 5 | 7 | 10
  answers: Record<string, string>
}

GameSession {
  id: string
  player: PlayerProfile
  chapters: ChapterResult[]
  finalTier: string
  story: StoryOutput
  createdAt: Date
  shareCode: string | null
}

ChapterResult {
  chapterNumber: number
  storyBeat: string
  typingSentence: string
  accuracy: number
  tier: string
  nextStoryBeat: string
}

StoryOutput {
  fullText: string
  illustrations: string[]  // image URLs
  visualStyle: VisualStyle
}
```

## 10. Open Questions

1. **Monetization:** Free forever? Freemium (free plays per day, pay for unlimited)? Pay for premium visual styles?
2. **Age gating:** Horror genre needs content guardrails. How dark can stories get?
3. **Image generation costs:** AI illustrations at game-end could get expensive at scale. Cache common scenes? Limit to paid tier?
4. **Typing on mobile:** Virtual keyboards are a different experience. Adapt the mechanic or accept it's desktop-first?
5. **Story length vs. AI cost:** Each chapter = 1 API call. A 10-chapter game = 10+ calls. Acceptable cost per session?
